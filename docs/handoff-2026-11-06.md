  active — the bot attacks when the cooldown is ready and then resumes walking,

- **Recovery works:** below the configured HP % the bot sits and waits for full

## Why Gameforge once said "Ve hře"

This was the stale state after the 15:32 crash; it cleared when the client was
started again and is not the current state. The crash happened **right after**
the skill hook captured a skill packet.
Later, with the fixed build, the live log showed both kinds of cast:

```
[SEND] u_s 0 3 5160
[RECV] su 1 14881134 3 5160 866 ...    # normal auto-attack
[SEND] u_s 10 3 5161
[RECV] su 1 14881134 3 5161 876 ...    # a cast skill
```

The first hook implementation ended with `ret` after replaying the original
call. `Memory::Hook` patches a call site with a **JMP**, not a CALL, so no
return address was on the stack. The fixed stub ends with
`jmp *ntpl_skill_jmp_back` (`call_site + 5`). See
[hooking.md](hooking.md#the-skill-packet-hook).

## Auto-attack test (verified live; use as a regression procedure)

1. Stand the character (`rest 1 1 <charId>` toggles; sitting blocks movement
   and can cancel skills).
2. In the GUI Map/Bot tab set **Skill = 0** (normal attack), **Auto-attack**
   on, Range ~10, Cooldown ~3, **Pickup** on, **Loot** 3. Draw a path toward
   monsters or stand near one.
3. Press **Start**. The bot attacks monsters and picks up your drops at its
   feet (it does not walk to distant drops yet).
4. Expected log:

   ```
   [SEND] ncif 3 <monsterId>
   [SEND] u_s 0 3 <monsterId>
   [RECV] su 1 14881134 3 <monsterId> 866 ...
   ```

   `su` with damage is the success signal; the engine records it in
   `world.combat` / `last_skill`. `cancel 0 0 -1` means the target/state was
   not usable (out of range, dead, or sitting); `cancel 0 866 -1` means the
   GUI is still set to 866.

## Important addresses (this client build)

All are build-specific; every C++ consumer validates its signature/prologue
and fails soft (`NOT-FOUND` / `MOVE: client build mismatch`).

| What | Address / layout |
|---|---|
| recv hook site | `0x004DBB4D` (5-byte `call rel32`) |
| send hook site | `0x004EB5C4` (6-byte prologue) |
| TNTClient global | `0x0055AA84` |
| Client MoveTo | `0x00565E88`; EAX=player object, EDX=`x \| (y << 16)`, ECX=flags, one stack arg |
| Local player | `[[0x00792468]]`; int16 x at +4, int16 y at +6, uint32 char id at +0x24 |
| `u_s` builder strings | `0x72D630` (`u_s `), `0x72D640` (`u_s`) |
| Skill capture call | call site `0x0072D5B2` → `0x004EB610`; packet in ECX |
| Walk checksum | `1 if (x + y) % 3 == 1 else 0` |

`MOVE|x y` and `POS` are host → DLL commands; see [ipc.md](ipc.md) and
[live-session-2026-11-06.md](live-session-2026-11-06.md).
