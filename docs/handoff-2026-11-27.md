## TARGET selection re-derived for 0.9.3.3262 (DLL 0.3.3)

The first live tamer run (GUI 0.9.12, DLL 0.3.1) showed every `TARGET` command
answering **`client build mismatch`** in the bot log, so every monster got
blocked, the tamer switched targets every tick and no `Tame` cast ever went
out. DLL 0.3.1 re-derived POS/MOVE/speed table for the 2026-11-25 client but
left the TARGET selector at the 0.9.3.3261 addresses.

Found in the **running** client (Linux PID 1818297 = Windows PID 836; the
runtime-unpacked code is not in the on-disk PE sections):

- selector prologue (unchanged signature `53 56 57 8B F2 8B F8 85 F6`)
  scanned in the live code range: **`0x005699D0`** (was `0x0057A0E4`). Its
  body checks entity `+0x33` alive, `+0x8` id, `+0xA9 != 4`, stores the
  entity at controller `+0x34` and calls the `ncif` send — same function.
- the client's own click handler at `0x0056400A` does
  `mov eax, [0x007944F0]` and calls the selector with that object, so the
  **controller global is `0x007944F0`** and it holds the controller pointer
  directly (one load; the old build used a holder and two loads). Verified:
  `[0x7944F0] = 0x252F1A08`, its vtable is in the module, `+0x34` held the
  then-selected partner entity.

DLL **0.3.3** updates `clienttarget.cpp` (`kSelector = 0x005699D0`,
`kSelectionGlobal = 0x007944F0`, `resolve_controller` one dereference). A
**game-client restart** is needed to load it.

Host 0.9.13 (applies with a GUI restart, no game restart) also stops a
build-mismatch `TARGET ... ERR` from blocking the entity or pausing combat:
it disables DLL TARGET for the session, logs the hint and falls back to
injected `ncif`. That keeps the old DLL from churning, but the client's own
selection is what makes `u_s` land, so the tamer needs DLL 0.3.3.

## The tamer (host 0.9.12)

Map/Bot → **Pet tamer** frame: **Tame monsters** toggle, **Monster vnum**
(333 = Chicken), **Tame slot** (1), **Hit until HP ≤** (25%) and a live line
with the pet slots and the run's tame count. Path **Start**/**Stop** run it;
with the toggle on the bot hunts the vnum instead of its normal combat. The
settings are saved as `tame`, `tame_vnum`, `tame_slot`, `tame_hp_pct`.

Per 50 ms tick: keep the nearest target within 15 cells → walk into range
(map A* or a 3-cell `MoveTo` on a map without data, e.g. Miniland) → Whip
until the `st` HP is at or below the limit → Tame and wait for a `msgi`
result → pre-damage the next chicken during the 15 s cooldown → repeat. It
stops on Stop, 1887 (pet slots full), 2631 ×3, three casts with no answer, or
2623.

Engine additions: `Entity.hp`/`hp_max` from `st`, `WorldState.pets` from
`sc_p`/`p_clear`, `WorldState.last_message_id`/`message_seq` from `msgi`.

**Live status: not yet run against the game.** The smoke
(`gui_tame_smoke.py`) covers the whole loop against a fake server. The live
client's pet list is currently full (8/8), so the server would answer 1887;
the first live run should start after a slot is freed.
