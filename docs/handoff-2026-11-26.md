## Client build and DLL 0.3.1

The 2026-11-25 Gameforge maintenance updated `NostaleClientX.exe` from
**0.9.3.3261 (build 6104)** to **0.9.3.3262 (build 6124)**. DLL 0.3.0's
hardcoded addresses were for 3261, so `POS` answered
`player object not readable` on every poll and `MOVE` reported a build
mismatch.

Re-derived from the running 3262 client and verified against its player
object (x/y 96,62, char id 7001):

| what | 0.9.3.3261 | 0.9.3.3262 |
|---|---|---|
| player global | `0x007954B4` | **`0x007964BC`** |
| chain | `[global] -> holder -> player` | `[0x7964BC] -> 0x927E7C -> player` |
| MoveTo | `0x00576920` | **`0x0056620C`** (same 13-byte prologue) |
| speed setter | `0x00492938` | unchanged `0x00492938` |
| speed table | `0x0078A3C8` | **`0x0078B3C8`** |

The speed-table references in 3262 use both the old `opcode 85 disp32` and
the indexed `opcode modrm sib disp32` (`D8 34 85 C8 B3 78 00`) forms; the
DLL now patches both (11 references). Player layout `+4/+6/+0x24/+0xA9` and
the entity speed byte `+0xAA` are unchanged.

The DLL is now **0.3.1** (`linux/src/dll/config.h`), built at
`linux/build/PacketLogger.dll`. It takes effect only after a **game-client
restart/re-inject**. The host throttles the repeated POS error to one line
per distinct error (a successful POS clears the latch).

Docs updated: [protocol/movement.md](protocol/movement.md), [ipc.md](ipc.md),

## NosBazar changes

### Row attribution by item name

A saved Nostale-NB search group can mix different items that share a NosMall
base vnum. `Partner Skill Ticket (Single)` (5931) and `(All)` (5932/9110)
were one group, and the Monitor took the minimum across all of them, showing
an (All) price under a (Single) row. The controller
(`ntpl/bazar.py`) now takes a `vnum_name` resolver:

- `item_identity_name` resolves the row's real Item.dat name (item vnum first,
  then the search group);
- `item_search_vnums` searches only the vnums with that name (same-name
  aliases such as 5931/9109 still compete; a different name is excluded);
- `_cheapest_listing` attributes the answer to the same name; an answer with
  only a different item's listing yields `no listings`, not a foreign price;
- names are resolved at answer time, so an async name load mid-pass is
  honoured; without a resolver the historical group minimum is kept.

The GUI passes `_bazar_vnum_name`; the editor's Search-vnums tooltip and
[bazar.md](bazar.md) explain the narrowing. `tracked_vnums` and the
inventory scan follow the same name-aware rules: a differently named group
sibling is added as its own row, a namesake is not.

### Monitor search and copy

- A search box above the two Monitor tabs filters both views by real item
  name, the configured label, or a vnum. The info line counts matches and
  how many **Only priced** hides; no-match and no-priced-match have their own
  empty states.
- Every Monitor row has a flat **Copy** button for the real item name; the
  Item cell is selectable text and keeps the **Copy item name** right-click
  menu. Relist rows have a Copy button and the same menu; Items/Inventory
  keep right-click copy.

### Relist character handling

The name is no longer typed anywhere:

- `BazarListing` carries the `rc_blist` owner id (field 1);
- own listings are matched by that id against `world.self_id`, falling back
  to the seller-list owner id (the seller tab lists only our listings) when
  the position packet was missed;
- `start_relist` no longer requires `config.character`; the name stays only
  as a fallback for matching;
- the Relist section has no **Character** field; its info line uses the
  detected name (or omits it) and never says "character missing";
- names are learned from the self `in 1` spawn (the whole 16 MB-capped DLL
  log is searched, not just the tail) and from the party/raid list `rdlst`
  (`_on_party_list`), with the config as the last fallback.

### Select all / Unselect all

The Relist section has standalone **Select all** and **Unselect all**
buttons next to **Remove from relisting**. They select/clear the visible rows
(respecting **Only relisting**) so they combine with **Group actions… →
Relist selected / Stop relisting selected** without a menu round trip.

### Items tab merge and compact Monitor (follow-up)

The Inventory tab and the old Items editor are now one **Items** tab; the
second-level navbar is **Items / Relist / Monitor / Configuration**.

- The Items list is one searchable set of every available item: the
  configured rows plus every distinct inventory template. Each row has a
  **Monitor** and a **Relist** tick. Ticking an inventory row creates it
  first; the Relist tick also fills vnum/tab/stack and sets floor 1. A
  configured row's ticks only switch `enabled`/`relist`.
- Selecting a row opens the full editor on the right (an inventory row
  shows a draft until Save). **Add to Monitor / Add to Relist** apply to a
  Ctrl+click selection; **Import…** holds NosMall and the full Item.dat
  picker; **⋯** holds Rescan inventory, Price all inventory, Add whole
  inventory, the bulk Monitor/Relist switches and the selection actions.
- The Monitor tab lists only monitored items (the Monitor tick is the
  master switch) and its four button rows are one compact toolbar:
  **Add from Items**, **Add…** (whole inventory / Item database…) and
  **Actions…** (monitor/stop the shown or selected rows, select/unselect,
  Open full editor). The old Only monitored checkbox is gone.
- Relist shows only the relist set by default (**Only relisting** is on;
  turn it off to browse every configured item). The list also filters out
  disabled items, matching `relist_items()`. **Add from Inventory** was
  removed: the Relist tick in Items is the way in.
- Screenshots: `gui-bazar-items.png` and `gui-relist.png` regenerated,
  `gui-inventory.png` removed and the shot tool's inventory mode dropped.
- The WIP's inconsistent render-method name (call sites used
  `_bazar_render_monitor_items` while only `_bazar_monitor_render_items`
  existed) was fixed earlier in the session.
- Covered by `gui_bazar_monitor_items_smoke.py` and the updated
  inventory/relist smokes.

### Full Item.dat catalog and config import (follow-up 2)

- **Items** now lists **every Item.dat row** (about 7,805) in a virtualized
  `Gtk.ColumnView` (Monitor / Relist / Item / Vnum / Where / Cost), plus
  configured rows the DB lacks and inventory-only vnums. The search filters
  all rows; Where annotates the live inventory. Ticking a DB row creates a
  monitor-only item (Relist also sets floor 1 and fills vnum/tab/amount from
  the bag). Rendering all 7,805 rows takes ~0.16 s; a toggle is an idle
  rebuild and does not refill unsaved editor values.
- **Items → Import…** gained **Import config (add)…** (merge, skip
  duplicates by name or vnum) and **Replace with config…** (confirmation,

  7,805 catalog rows, 17 configured / 17 ticked / 17 monitor rows; add-import
